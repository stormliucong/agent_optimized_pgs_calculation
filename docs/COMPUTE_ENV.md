# Compute environment and software versions

| Component | Specification / version | Role in the pipeline | Notes |
| --- | --- | --- | --- |
| GPU | NVIDIA GB10 (Grace–Blackwell superchip, compute capability 12.1), in an HP ZGX Nano G1n AI Station | Executes the sparse dosage × weight products (cuSPARSE `csrmm`) and the dense GEMM path (cuBLAS) that dominate scoring time | Single GPU; all reported GPU timings are single-device. `nvidia-smi` reports no separate frame-buffer size because memory is unified with the host. |
| GPU memory | 128 GB unified LPDDR5X | Holds the genotype tile, the CSR weight matrix and the score accumulator without host↔device staging | Physically the *same* pool as host RAM — a large host-side allocation directly reduces what the GPU can use. This drove the tiling/sub-tiling logic in `baseline_cohort_memory_safe.py`. |
| CPU cores | 20 (Arm aarch64: 10 × Cortex-X925 @ 4.00 GHz + 10 × Cortex-A725 @ 2.86 GHz) | Multiprocess VCF parsing, gzip decompression, variant harmonisation, and the CPU reference implementations | Heterogeneous big.LITTLE-style layout; worker counts are capped adaptively rather than fixed at 20. No x86 fallback — bioconda has no linux-aarch64 `plink2` build, so `plink2` was built from source. |
| Host RAM | 128 GB unified (125,446,400 kB = 119.6 GiB reported by the kernel) | Buffers decompressed VCF tiles and the per-cohort dosage matrices before transfer | Shared with GPU memory (see above), so the practical host budget during GPU phases is well under 119 GiB. 16 GiB swap is configured but not relied on. |
| Storage | 3.6 TB local NVMe SSD (`ESL04TBTLCZ-27J4-TYN`), ext4 on `/dev/nvme0n1p2` | Holds `1kg_data/` per-individual VCFs, the `PGSCatelog/` scoring files, and all `*_workspace/` outputs | Non-rotational, single local device — no network filesystem in the I/O path, so decompression throughput (not seek latency) is the input-side bottleneck. |
| CUDA toolkit | 13.0.88 (`nvcc`, `/usr/local/cuda-13.0`) | Provides headers/NVRTC (13.0) for CuPy's runtime kernel compilation | CuPy itself is the `cupy-cuda12x` wheel and links its own bundled CUDA **12.9** runtime, so two CUDA runtimes coexist: 12.9 (used by CuPy) and 13.0 (system toolkit). |
| GPU driver | 580.95.05 (CUDA driver API 13.0) | Backward-compatible host for the bundled 12.9 runtime | Driver-level CUDA 13.0 > runtime 12.9, which is the supported direction. `libcusolver.so.11` is absent, so CuPy's cuSOLVER path is unavailable — unused by this pipeline. |
| CuPy | 14.1.1 (`cupy-cuda12x`) | GPU array layer for all optimised scorers (`optim_src/gpu_pgs.py`, `src_cohort/gpu_pgs.py`, `baseline_cohort_memory_safe.py`) | Installed both system-wide and in the `--system-site-packages` run venvs, so the venv and non-venv paths use the identical build. |
| cuSPARSE | 12.6.3 (`cusparseGetVersion` → 12603) | `csrmm` sparse-dense product: the core scoring kernel | Ships inside the `cupy-cuda12x` wheel, not with the system CUDA 13.0 toolkit. Accumulation order is not deterministic across launches — float32 `csrmm` summation-order effects were reconciled by scoring in float64 where exact agreement was required. |
| ISA-L (igzip) | ISA-L **2.31.1**, via `python-isal` **1.8.0** | Fast gzip decompression of the input VCFs, replacing stdlib `gzip` on the hot read path | **Version-pinned deliberately: the reported wall-clock timings depend on it.** `run_1kg.py`/`run_val.py` build a `--system-site-packages` venv at `<workspace>/.venv` and `pip install isal` into it so the optimised scorers use `isal.igzip`; `--no-venv` disables this and silently falls back to stdlib `gzip`, which changes timings. |
| Python | 3.13.11 (CPython, aarch64) | Interpreter for every scorer and for the `run_1kg.py` / `run_val.py` harnesses | The run venvs inherit this interpreter via `--system-site-packages`. Separate from the Python 3.12 inside the pgsc_calc conda environments. |
| NumPy / pandas | NumPy 2.4.1 / pandas 3.0.0 (SciPy 1.18.0 alongside) | Variant tables, weight joins, dosage assembly, and the CPU baseline arithmetic | PyArrow is *not* installed, so pandas 3.0 falls back to its NumPy-backed string dtype; NumPy 2.x semantics (no implicit integer overflow wraparound in scalars) apply to the packed int64 key scheme. |
| Operating system / kernel | Ubuntu 24.04.4 LTS (Noble Numbat), kernel 6.14.0-1015-nvidia, aarch64, glibc 2.39 | Host OS for all runs | NVIDIA-flavoured kernel required for GB10 unified-memory support. aarch64-only: several bioconda packages have no build for this platform. |
| Container image | None — all scoring runs execute bare-metal on the host | — | The custom scorers run directly under the host Python/venvs. The `pgsc_calc` v2.3.0 comparator is run through Nextflow with `-profile conda` (environments materialised under `pgs_cal_workspace/envs/` and `pgs_cal_workspace/conda_envs/`), **not** Docker or Singularity, because no linux-aarch64 image was available; `local.config` redirects the `plink2` process to a host-built binary. Consequently there is no image digest to report. |
